# 增产策略优化算法详解

> 本文档详细描述在 DAG 层级动态变化约束下，寻找全局最优增产策略的两阶段优化算法。
> 配合 `core-algorithm.md` 第14-15节阅读。

---

## 1. 问题背景

### 1.1 DAG 层级的两层功能

| 功能 | 说明 |
|------|------|
| **遍历顺序** | 按 DAG 顺序（低→高）遍历增产选择，可实现完美剪枝 |
| **计算顺序** | 给单次资源消耗计算提供迭代顺序（上游先算） |

### 1.2 核心矛盾

增产剂本身是物品，有自己的生产链。**选择增产剂 = 添加新的原料依赖**。

规则：`产物DAG层级 > 所有原料的DAG层级`

因此：低 DAG 物品选择了高 DAG 增产剂 → 增产剂层级被拉低 → DAG 结构变化。

```
例：物品a(dag1) 选择 MK2(dag3) 作为增产剂
→ MK2 变成 a 的原料
→ a 的层级变为 dag4（> MK2的dag3）
→ DAG 结构改变
```

这形成了**循环依赖**：遍历顺序依赖 DAG，DAG 依赖增产选择。
而且这种影响**不是迭代收敛的，也不是双向线性的**。

---

## 2. 关键洞察

> **不需要等所有低层级物品都确定，只需要等该物品的所有上游物品确定即可。**

- 优化遵循 DAG 层级顺序的**本质逻辑**：先确定原料的增产策略，再确定产物的
- 这样数学上可以证明与全局最优增产策略相符
- 但"所有低层级物品都确定"是充分条件，不是必要条件
- **上游物品必然在更低层，但更低层的物品不全是上游**——这是包含关系

```
         所有低层级物品
        ┌──────────────┐
        │  上游物品     │  ← 只需要这部分确定
        │  ┌────────┐  │
        │  │        │  │
        └──┤────────┤──┘
           │ 非上游  │
           └────────┘
```

## 3. 三级递进假设

由浅入深，逐步放开约束。

### 基础数据（无增产剂时的 DAG 层级）

```
MK1: dag1（原料：铁矿）
金刚石: dag2（原料：高能石墨 dag1）
MK2: dag3（原料：MK1 dag1 + 金刚石 dag2）
碳纳米管: dag1
MK3: dag4（原料：MK2 dag3 + 碳纳米管 dag1）
```

### 第一层：只能选比自己层级低的增产剂

- DAG 层级**不变**
- 标准从低到高遍历即可
- 任何物品的原料增产策略都先确认了

### 第二层：增产剂产线不能用高于自己层级的增产剂

- DAG 层级**变化但无循环组**
- 遍历到 dag1 物品 a：
  - a 选 MK1 → a 变为 dag2 → 先递归处理 MK1 的增产选择
  - a 选 MK2 → a 变为 dag4 → 先递归处理 MK2（MK2 的原料金刚石和 MK1 也要递归处理）
  - a 选 MK3 → 同理
- **递归必然终止**：增产剂产线只能选低级增产剂，不会形成环

### 第三层：完全自由选择（核心算法）

- DAG 层级**变化且可能出现循环组**
- 增产剂产线也可以用高于自己层级的增产剂
- 必然出现增产剂循环组（SCC）
- 需要递归 DFS + 动态 SCC 分析

## 4. 核心算法：两阶段优化

### 4.1 算法概述

新的优化算法采用两阶段策略，将问题分解为两个独立的子问题：

1. **第一阶段：循环组优化** - 处理复杂的循环依赖关系
2. **第二阶段：单物品优化** - 处理独立的物品优化

这种分离使得算法逻辑更清晰，效率更高，且易于维护和扩展。

### 4.2 第一阶段：循环组优化

#### 目标

找出并优化所有循环组（SCC 大小 > 1），因为循环组内的物品相互依赖，必须整体考虑。

#### 算法流程

```
1. 初始化配置
   - 强制所有物品使用允许的最高等级增产剂
   - 选择第一个可选模式（优先增产，其次加速）

2. SCC 分析
   - 在最高等级配置下计算一次 SCC
   - 找出循环组（SCC 大小 > 1）

3. 坐标下降优化
   - 对循环组内每个物品：
     - 尝试所有增产选择（7种）
     - 计算每种选择下的总耗电
     - 选择耗电最小的策略
   - 重复迭代直到收敛（无改善）

4. 持久化策略
   - 将循环组的最优策略保存到 resolved Map
   - 应用策略到当前方案
```

#### 坐标下降算法

坐标下降是一种迭代优化算法，每次优化一个变量，保持其他变量不变：

```
初始化：所有物品 = 无增产
重复：
  对于循环组中的每个物品 i：
    bestChoice = 当前选择
    bestCost = 当前成本
    对于物品 i 的每种增产选择 choice：
      临时应用 choice
      计算新成本
      如果新成本 < bestCost：
        更新 bestChoice 和 bestCost
    应用 bestChoice
  如果本轮无改善：停止
```

### 4.3 第二阶段：单物品优化

#### 目标

优化所有非循环组物品，按依赖顺序逐个确定最优策略。

#### 算法流程

```
1. 重新 SCC 分析
   - 基于第一阶段结果计算 SCC
   - 按 SCC 正序（原矿→产物）排列

2. 逐个优化
   - 遍历所有非循环组物品（跳过已持久化的）
   - 对每个物品：
     - 尝试所有增产选择
     - 计算每种选择下的总耗电
     - 选择耗电最小的策略
     - 持久化到 resolved Map

3. 不需要递归
   - 循环组已在第一阶段处理
   - 单物品之间无循环依赖
   - 按 SCC 正序保证上游先确定
```

### 4.4 选择分类

对于增产方式不受限的物品，有 7 个选择：

```
{无, MK1加速, MK1增产, MK2加速, MK2增产, MK3加速, MK3增产}
```

| 选择类型 | 是否产生新分支 | 处理方式 |
|---------|:------------:|---------|
| 无增产 | 否 | 直接计算 |
| 低级增产剂（< 物品层级） | 否 | 直接计算 |
| 同级加速 ↔ 增产 | 否 | 直接计算 |
| 高级增产剂（> 物品层级） | **是** | 形成/扩大 SCC |

### 4.5 SCC 分析优化

新算法只进行两次 SCC 分析：

1. **第一次**：在最高等级配置下分析，找出循环组
2. **第二次**：在循环组优化后重新分析，确定单物品优化顺序

相比旧算法每次尝试都分析 SCC，新算法显著减少了计算量。

### 4.6 自循环处理

自循环（如增产剂自喷）不产生新依赖，用等比数列直接计算：

```
实际产出 = 基础产出 / (1 - 自消耗比例)
```

不触发 SCC 分析。

## 5. 完整模拟

以 MK1(dag1)→MK2(dag3)→MK3(dag4) 为例，演示两阶段优化算法的执行过程。

### 场景设定

```
MK1: dag1, 原料: 铁矿
MK2: dag3, 原料: MK1(dag1) + 金刚石(dag2)
MK3: dag4, 原料: MK2(dag3) + 碳纳米管(dag1)
金刚石: dag2, 原料: 高能石墨(dag1)
碳纳米管: dag1
```

### 第一阶段：循环组优化

#### Step 1: 初始化配置

强制所有物品使用允许的最高等级增产剂（假设为 MK3）+ 第一个可选模式（假设为增产）：

```
MK1: MK3增产
MK2: MK3增产
MK3: MK3增产
金刚石: MK3增产
碳纳米管: MK3增产
```

#### Step 2: SCC 分析

在最高等级配置下计算 SCC，找出循环组：

```
SCC 分析结果：
  - 循环组 #1 = {MK1, MK2, MK3, 金刚石, 碳纳米管}（大小 > 1）
```

#### Step 3: 坐标下降优化

对循环组内每个物品进行坐标下降迭代：

```
初始状态：所有物品 = MK3增产
初始耗电：1.23 GW

第1轮：
  MK1: 尝试 7 种选择 -> MK2增产 最优 (1.18 GW)
  MK2: 尝试 7 种选择 -> MK3加速 最优 (1.15 GW)
  MK3: 尝试 7 种选择 -> MK2增产 最优 (1.12 GW)
  金刚石: 尝试 7 种选择 -> MK1增产 最优 (1.10 GW)
  碳纳米管: 尝试 7 种选择 -> MK1加速 最优 (1.08 GW)

第2轮：
  MK1: 尝试 7 种选择 -> 无改善
  MK2: 尝试 7 种选择 -> 无改善
  MK3: 尝试 7 种选择 -> 无改善
  金刚石: 尝试 7 种选择 -> 无改善
  碳纳米管: 尝试 7 种选择 -> 无改善

收敛，停止迭代。
```

#### Step 4: 持久化策略

将循环组的最优策略保存到 `resolved` Map：

```
resolved.set('MK1', { strategy: { level: 2, mode: 2, name: 'MK2增产' }, cost: 1.08 GW })
resolved.set('MK2', { strategy: { level: 3, mode: 1, name: 'MK3加速' }, cost: 1.08 GW })
resolved.set('MK3', { strategy: { level: 2, mode: 2, name: 'MK2增产' }, cost: 1.08 GW })
resolved.set('金刚石', { strategy: { level: 1, mode: 2, name: 'MK1增产' }, cost: 1.08 GW })
resolved.set('碳纳米管', { strategy: { level: 1, mode: 1, name: 'MK1加速' }, cost: 1.08 GW })
```

### 第二阶段：单物品优化

#### Step 5: 重新 SCC 分析

基于第一阶段结果重新计算 SCC：

```
SCC 分析结果：
  - 所有物品已处理，无新的循环组
```

#### Step 6: 逐个优化

按 SCC 正序遍历所有非循环组物品（跳过已持久化的）：

```
需要优化的物品：0 个（所有物品已在循环组中处理）
```

### 最终结果

```
初始耗电：1.23 GW
最终耗电：1.08 GW
耗电减少：0.15 GW (12.2%)
```

### 算法执行流程图

```
开始
  |
初始化配置（最高等级 + 第一模式）
  |
SCC 分析 -> 找出循环组
  |
循环组存在？
  |-- 是 -> 坐标下降优化 -> 持久化策略
  |-- 否 -> 跳过
  |
重新 SCC 分析
  |
按 SCC 正序遍历非循环组物品
  |
逐个优化（尝试所有选择，选最优）
  |
持久化策略
  |
返回最优方案
```

## 6. 持久化与剪枝

### 6.1 持久化的正确性

当一个物品（或循环组）的**所有上游都已确定策略**后，遍历其所有增产选择得到的最优策略可以**永久持久化**。

原因：上游不会再变 → 局部最优 = 全局最优 → 不可推翻。

### 6.2 两阶段持久化

新算法中的持久化分为两个阶段：

1. **第一阶段持久化**：循环组优化完成后，将循环组内所有物品的最优策略持久化到 `resolved` Map
2. **第二阶段持久化**：单物品优化时，每个物品确定最优策略后立即持久化

### 6.3 剪枝效果

```
循环组成员持久化后 -> 不再参与第二阶段优化
单物品持久化后 -> 不再参与后续物品的优化
-> 减少重复计算，提高效率
```

## 7. 算法特性

### 7.1 算法优势

新算法相比旧算法有以下优势：

| 特性 | 旧算法（递归 DFS） | 新算法（两阶段优化） |
|------|-------------------|---------------------|
| **逻辑清晰度** | 递归调用链复杂，难以调试 | 两阶段分离，逻辑清晰 |
| **效率** | 每次尝试都 SCC 分析 | 只进行两次 SCC 分析 |
| **精确性** | 可能遗漏某些组合 | 循环组用坐标下降遍历，覆盖所有可能 |
| **可扩展性** | 递归逻辑难以扩展 | 为未来算法预留接口 |
| **可维护性** | 状态回溯复杂 | 无递归，状态简单 |

### 7.2 完整性

- **不遗漏**：循环组内所有物品的所有增产选择都会被尝试
- **必然终止**：坐标下降算法在无改善时停止，保证收敛
- **最优性**：循环组优化找到局部最优，单物品优化找到全局最优

### 7.3 复杂度

#### 第一阶段：循环组优化

- 时间复杂度：`O(C * N * M)`
  - C：坐标下降迭代次数（通常 < 10）
  - N：循环组物品数
  - M：每个物品的增产选择数（最多 7）
- 空间复杂度：`O(N)` 存储当前选择状态

#### 第二阶段：单物品优化

- 时间复杂度：`O(K * M)`
  - K：非循环组物品数
  - M：每个物品的增产选择数（最多 7）
- 空间复杂度：`O(1)` 逐个处理

#### 总体复杂度

- 远小于 `7^N`（旧算法的理论复杂度）
- 实际运行时间主要取决于 SCC 分析和耗电计算的开销

## 8. 多目标策略支持

### 8.1 概述

优化器支持多种优化目标函数，用户可根据需求选择不同的优化策略。

### 8.2 支持的策略

| 策略标识 | 名称 | 目标函数 | 说明 |
|---------|------|---------|------|
| `min_power` | 最小电力 | `totalEnergyCost` | 最小化总耗电（生产电力 + 采集电力），默认策略 |
| `min_raw_ore` | 最小原矿 | `totalRawOre` | 最小化原矿消耗总量（无权重累加） |

### 8.3 原矿识别逻辑

原矿判定标准（与 `result.jsx` 一致）：

1. 物品在 `settings.mineralize_list` 中（用户标记为原矿化）
2. 物品的配方无原料输入且只有单一产物（天然原矿，如铁矿、铜矿等）

```javascript
function isRawOreItem(itemId, recipeData, mineralizeList) {
  if (itemId in mineralizeList) return true;
  for (const recipe of recipeData) {
    const outputs = recipe['产物'] || {};
    if (!(itemId in outputs)) continue;
    const inputs = recipe['原料'] || {};
    if (Object.keys(inputs).length === 0 && Object.keys(outputs).length === 1) {
      return true;
    }
  }
  return false;
}
```

### 8.4 策略对算法的影响

不同策略仅影响目标函数的选择，两阶段优化算法结构保持不变：

- **第一阶段（循环组优化）**：坐标下降使用对应目标函数评估成本
- **第二阶段（单物品优化）**：逐个优化时使用对应目标函数评估成本

```javascript
// 根据策略选择计算函数
const calculateResult = strategy === 'min_raw_ore' ? calculateRawOre : calculatePower;

// 获取目标值
function getObjectiveValue(result, strategy) {
  if (strategy === 'min_raw_ore') return result.totalRawOre ?? 0;
  return result.totalEnergyCost;
}
```

### 8.5 返回值扩展

优化器返回值增加策略相关字段：

```javascript
{
  optimalScheme: currentScheme,
  initialPower,           // 初始耗电
  optimalPower,           // 最终耗电
  strategy,               // 使用的策略标识
  initialObjective,       // 初始目标值
  optimalObjective,       // 最终目标值
  changes,                // 策略变更列表
  processedCount,         // 已处理物品数
  totalCount              // 总物品数
}
```
