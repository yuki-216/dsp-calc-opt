# 设计规格文档

## 项目概述

在现有开源项目 [DSPCalculator/dsp-calc](https://github.com/DSPCalculator/dsp-calc) 基础上，进行功能修剪和新增，实现：
- 基础生产线计算（保留原有功能）
- 燃料计算模块（新增）
- 增产剂自动优化（新增）

### 技术选型

| 项目 | 选择 | 说明 |
|------|------|------|
| 基础项目 | dsp-calc | 已实现核心计算功能 |
| 框架 | React 18 | UI组件库 |
| 构建 | Vite | 快速开发服务器 |
| 样式 | Bootstrap 5 | UI框架 |
| 求解器 | javascript-lp-solver | 线性规划 |
| 状态 | React Context | 全局状态管理 |

### 开发环境

```bash
# 安装依赖
npm install

# 启动开发服务器
npm run dev

# 访问地址
http://localhost:5173

# 编译成静态文件（可选）
npm run build
```

## 核心模块

### 数据加载 (GameData.jsx)

- 加载 Vanilla.json（原版游戏数据）
- 解析配方、物品、设施数据
- 构建物品ID映射表

### 核心计算 (global_state.jsx)

- 构建物品依赖图
- 拓扑排序 + LP求解器调用
- 计算生产需求

计算流程：
```
用户需求 → 构建物品图 → 拓扑排序 →
  ↓
简单物品：迭代计算
复杂物品：LP求解
  ↓
输出结果
```

### 新计算引擎 (src/engine/)

三段式计算架构，用矩阵求逆替代LP求解器：

```
用户需求 → DAG层级计算 → 单位成本计算 → 按需求量放大 →
  ↓           ↓              ↓              ↓
BFS构建图   SCC检测      系数表+矩阵求逆   需求×单位成本
  ↓           ↓              ↓              ↓
依赖图      循环组         成本展开        资源汇总
```

**关键设计**：
- 系数表追踪成本，`$`前缀区分执行次数
- SCC循环组用矩阵求逆求解，不需要关键物品断开
- 逆生产机制自动抵消多余产物
- 虚拟"解"配方处理多需求

### 配方方案 (scheme_data.jsx)

- 管理配方选择
- 管理增产剂配置
- 管理成本权重

### UI组件

| 组件 | 功能 | 文件 |
|------|------|------|
| NeedsList | 需求列表管理 | needs_list.jsx |
| Result | 结果显示 | result.jsx |
| BatchSetting | 批量预设 | batch_setting.jsx |
| Settings | 设置面板 | settings.jsx |
| Recipe | 配方显示 | recipe.jsx |
| ItemSelect | 物品选择 | item_select.jsx |

### 循环处理机制（旧）

1. 构建物品依赖图
2. 找入度/出度为0的物品
3. 无法排序时，找度数最高的物品作为"关键物品"
4. 关键物品视为免费输入（断环），后续由LP处理

### LP求解器（旧）

适用场景：多来源物品、循环关键物品、外部供应物品。

### 新计算引擎算法

**三段式计算架构**：

1. **DAG层级计算**：BFS从需求出发构建依赖图，Tarjan SCC检测循环组
2. **单位成本计算**：系数表追踪成本，按SCC顺序展开：
   - 单节点SCC：直接代入依赖方
   - 多节点SCC（循环组）：构建矩阵，求逆求解
3. **按需求量放大**：需求量 × 单位成本 = 总资源消耗

**关键算法**：
- 系数表：`$`前缀区分执行次数，负数表示副产物
- 逆生产：负系数物品已有执行次数时，展开取消成本抵消
- 矩阵求解：直接构建目标矩阵A，单位频率常数项

## 项目阶段

### 阶段1：项目理解与有限优化

**目标**：复制源项目，在不改变核心功能逻辑的前提下，进行结构理解与有限优化。

#### 代码理解与增强

**允许**：
- 添加注释以辅助理解代码逻辑
- 注释掉未启用/无意义的功能代码
- 小范围命名优化（不改变跨模块结构）

**禁止**：
- 删除代码（用注释代替删除）
- 改变业务逻辑
- 改变函数调用关系
- 改变模块依赖结构

#### 无效代码处理规范

使用注释标记，而非删除。在注释中说明原因，保持代码可追溯性。

#### MOD相关代码处理

**决策**：保留所有MOD相关代码和数据

**原因**：
- 原项目MIT许可证允许修改和再发布
- 保留兼容性，减少工作量
- 便于未来可能的MOD支持

#### 操作确认规范

**任何代码修改前必须**：
1. 说明修改内容
2. 说明修改原因
3. 说明影响范围
4. 等待用户确认

### 阶段2：燃料计算

- 添加燃料选项
- 电力作为"产物"加入输出表格
- 默认电力配方在配置区设置
- 支持多电力方案（类似多配方）

### 阶段3：优化（简化版）

- 自动寻找最优增产剂配置
- 目标函数：最小化矿物瓶颈比
- 忽略占地瓶颈

### 阶段4：占地模块

两种占地计算方式：

| 模式 | 说明 |
|------|------|
| 无带模式 | 只考虑设备自身占地 |
| 有带模式 | 考虑实际占地（传送带、电力设备等） |

完善优化目标：`最小化 max(矿物瓶颈比, 占地瓶颈比)`
