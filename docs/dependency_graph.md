# 依赖图模块文档

## 概述

依赖图模块用于可视化显示戴森球计划游戏中物品之间的依赖关系（原料 -> 产物）。布局方向为从上到下，源节点（原材料）在上方，汇节点（最终产物）在下方。

两种显示模式的图都保证**无环**（纯 DAG），因此布局采用纯 Kahn 分层，无需 SCC 处理：
- **仅需求模式**：从引擎二部图 recipes 自建**无环投影**（`projectNeedsOnlyEdges`），去掉电力/喷涂增产剂消耗边。
- **全部配方模式**：基于原始配方表建边，天然不含电力/增产剂边。

## 文件结构

- `src/DependencyGraphPage.jsx` - 依赖图页面主组件
- `src/dependency-graph-edges.js` - 仅需求模式无环投影纯函数（`projectNeedsOnlyEdges`）
- `src/DependencyGraph.css` - 依赖图样式
- `src/engine/graph-utils.js` - 共享图算法（tarjanSCC 等），**仅被增产优化器消费**，依赖图页不使用

## 边方向

边存储方向为 `{from: 产物, to: 原料}`，即从产物指向原料。

构建邻接关系时交换赋值，使 `parents` 语义为上游原料、`children` 语义为下游产物，拓扑排序和布局代码的语义不变。

## 功能特性

### 1. 依赖关系展示
- 根据当前配方选择显示物品间的依赖关系
- 引线从原料指向产物（下方出，上方进）
- 起点使用蓝色实心圆点标记（出节点/原料端）
- 终点使用黑色实心圆点标记（入节点/产物端）
- 引线绕行算法：当引线经过非目标节点时，自动就近避让绕行
- **自环引线**：自依赖物品（如 X射线裂解中的氢）的引线从底部出线口出，绕左侧画贝塞尔曲线回到顶部进线口

### 2. 交互功能
- **缩放**：鼠标滚轮缩放
- **拖拽画布**：左键拖拽空白区域平移画布
- **拖拽节点**：左键拖拽**首层节点**调整位置（非首层节点不可拖动）
- **右键删除**：右键点击节点删除物品
- **恢复物品**：点击"已删除"按钮恢复物品
- **悬停高亮**：鼠标悬停节点时高亮直接上下游节点及连接到悬停物品的引线
- **图例高亮**：鼠标悬停图例项时只高亮对应类型的所有物品图标（引线淡化，不高亮），图例分三类：原矿、中间、最终
- **显示模式切换**：当需求表有物品时，点击"全部配方"/"仅需求"按钮切换显示模式
- **视角居中**：点击"视角居中"按钮恢复默认视角（scale=1, pan={x:0, y:0}）
- **自动居中**：每次切换到依赖图页面时自动居中视角（基于首层节点中心位置）
- **浏览器缩放**：浏览器缩放比例改变后自动重置视角

### 3. 显示模式

- **默认模式**：根据需求表是否有物品决定（有物品→仅需求，无物品→全部配方）
- **全部配方**：显示所有配方
- **仅需求**：只显示需求表相关配方
- **模式持久化**：不持久化（每次进入页面根据需求表重新判断）

#### 仅需求模式（自建无环投影）

不再复用核心引擎的 `edges`（引擎 edges 含 `物品→电力` 耗电边、`物品→喷涂增产剂` 消耗边，供优化器做**真实有环 SCC** 分组），而是调用 `projectNeedsOnlyEdges()` 从 `engineGraphData.graph.recipes` 自建无环投影：

- 对每个配方 `mainItem → 各 inputs 正系数`，仅保留 `k ∈ recipe_data[recipeId].原料`（**原始配方表**）的真实原料边——用原始表区分"真实原料"与"喷涂附加输入"（电力与喷涂增产剂都是引擎按方案附加进 inputs 的，不在原始表里）。
- 因此**去掉** `物品→电力` 与 `物品→喷涂增产剂` 消耗边；**保留** 增产剂配方内部真实链边（增产剂 Mk.III→Mk.II→Mk.I）与燃料链（`电力→燃料`）。
- **电力与增产剂作为独立需求节点**显示（即使无燃料配方，电力也保留为孤立节点）；需求表物品强制入节点；删除表过滤边与节点。

#### 全部配方模式

使用 `build_dependency_graph()` 函数，遍历所有物品的配方，基于**原始配方表** `recipe.原料` 建边（显式跳过 `电力`），不含电力/增产剂边，天然无环。显示时从全量数据中过滤已删除物品。

#### 建边逻辑

- 全部配方模式：`recipe_handled` Set 按配方去重，遍历每个配方的 `原料` 连接到所有 `产物`。
- 仅需求模式：`projectNeedsOnlyEdges` 内部用 `edge_set` 去重。

#### 自环处理

- **拓扑排序**：`from === to` 的边在邻接构建时跳过，不影响入度，物品正常参与排序
- **引线渲染**：自环边用贝塞尔曲线从底部出线口出，绕左侧回到顶部进线口

## 数据持久化

以下数据保存在 localStorage：
- `dependency_graph_deleted_items` - 已删除物品列表
- `dependency_graph_custom_positions` - 全部配方模式的自定义节点位置
- `dependency_graph_custom_positions_needs` - 仅需求模式的自定义节点位置

### 自定义位置应用规则

- 自定义位置仅对**首层节点**（`is_first_layer`）生效
- 合并时只覆盖 `x` 坐标（水平方向），`y` 坐标始终使用布局算法的计算值
- 物品离开首层后（如布局变化导致下移），其持久化位置自动失效，由布局算法重新计算
- 这确保了层级变化后物品不会因旧的持久化坐标而渲染到错误位置

## 技术细节

### 布局算法流程

图已保证无环，布局为纯 Kahn 分层 + 重心法优化（无 SCC 分解）：

1. **Kahn 分层**：`layer = 1 + max(parents' layer)`，原料层 0。防御：若出现环/孤立节点未获层级，兜底置层 0
2. **下移优化**：按层级从高到低（产物在前），尝试增大层级直到遇到产物同层。回退机制：原本是第一层（layer 0）的物品，如果下移只能移动1层，就保持第一层
3. **层间距计算**：根据每层引线密度动态调整（90px-115px）
4. **位置分配**：首层排列 + 重心法优化（两遍遍历，参考父子节点 x 均值），首层节点拖拽后触发重叠推开

### 共享图算法（graph-utils.js）

`tarjanSCC`、`compressToDag`、`dagTopologicalSort` 当前**仅被增产优化器**（`src/engine/proliferator-optimizer.js`）消费：优化器基于引擎 edges 自算 SCC 分组，依赖图页已不再使用这些算法。

### 引线路径生成

- **碰撞检测**：收集所有圆点坐标（按 y 分层存储），生成检测数组
- **检测方法**：在引线的 y 坐标范围内，计算引线在检测 y 处的 x 坐标，检查与圆点 x 的最小距离
- **绕行算法**：当检测到碰撞时，根据起点在圆点的左右判断避让方向，生成贝塞尔曲线绕行路径
- **控制点偏移量**：绕行时使用 `Math.min(50, dy / 2)`，普通曲线使用 `Math.min(35, dy / 3)`

### 节点类型

节点只区分三种类型（无循环分组框）：
- **原矿**（绿色边框 `#51cf66`）：入度为 0 的源节点
- **最终产物**（黄色边框 `#ffd43b`）：出度为 0 的汇节点
- **中间产物**（蓝色边框 `#4a9eff`）：其余所有节点

### 调试面板

点击右上角"层级"按钮可查看层级分布：
- 每层的物品列表及 DAG 层级值

## 使用方法

1. 在主页面点击导航栏的"依赖图"按钮进入
2. 鼠标悬停节点高亮其直接上下游节点和引线
3. 右键删除物品，左上角按钮恢复
4. 点击"视角居中"按钮恢复默认视角
5. 点击"全部配方"/"仅需求"按钮切换显示模式
